# Приём задачи

## Назначение

Task intake принимает вход владельца и определяет ближайший маршрут.

## Правила

1. Императивный запрос нового продукта фиксирует `intent`.
2. После первого запроса агент сначала завершает вход SoT по `sops/sot.md`; первый содержательный ответ начинает интервью, если обязательные слои ещё не закрыты.
3. Реализация открывается только отдельным `owner_decision`.
4. Начальный пакет интервью не включает route-разрешение. После `PRODUCT_INPUT` первоначальный продукт в `sot_files` переходит к discovery без выбора маршрута; новая задача принятого продукта в `sot_files` получает один выбор поддерживаемого маршрута; уже объявленный `sot_git` запрашивает `local_git_route` отдельной репликой.
5. Запрос на Git, выпуск, tag или GitHub write-действия требует отдельного решения владельца; исключение — автоматический baseline-bootstrap уже объявленного `SOT_MODE: sot_git` по `sops/sot.md`.
6. PLAN хранит ссылки `INTERVIEW_EVIDENCE_REF` и `OWNER_DECISION_REFS`.

## Остановка

Если агент сразу пишет код продукта без интервью, проход считается нарушенным и должен быть остановлен.
