# Управляемый проход агента

## Назначение

Процедура описывает управляемый проход агента внутри Product Unit.

## Порядок

1. Прочитать `AGENTS.md` и `SYSTEM.md`.
2. После первого запроса обработать mode-specific вход текущего `SOT_MODE` по `sops/sot.md` до интервью и файловых изменений; для `sot_github` external preflight предшествует local checker.
3. Проверить active PLAN.
4. Если поступил первый продуктовый запрос, начать обязательное интервью.
5. Не спрашивать `local_git_route` в начальном интервью; после фактического `PRODUCT_INPUT` запросить его отдельной репликой и получить отдельное явное разрешение до IE/OD и первой постоянной discovery-записи, если текущий режим `sot_git`.
6. Не писать продуктовый код до `interview_evidence` и `owner_decision`.
7. Следовать `sops/sot.md`: применять только capability текущего слоя и отдельно проверять маршрутное разрешение действий.
8. Выполнить проверки и clean-exit.

Bootstrap отсутствующего репозитория выполняет агент, а не Product Unit tools.

## Запрещено

1. Выводить решение владельца из собственной интерпретации запроса.
2. Создавать synthetic owner decision.
3. Создавать фиктивное interview evidence.
4. Выполнять release/tag или GitHub write-действия без отдельного решения.
