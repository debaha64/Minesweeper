# Чистое завершение

## Назначение

Clean-exit фиксирует завершение управляемого прохода.

## Отчёт

Отчёт разделяет:

1. что выполнено;
2. как изменён `ROAD -> BACK -> PLAN`;
3. какие файлы изменены;
4. какие проверки выполнены;
5. что намеренно не выполнялось;
6. blocker;
7. open item;
8. следующий шаг.

## SoT

Фиксировать `SOT_MODE`. В `sot_files` подтверждать, что путь `.git` не читался и Git CLI не вызывался. В `sot_git` фиксировать базовый commit, рабочую ветку, отсутствие remote и clean tree. В `sot_github` фиксировать repository identity, `origin`, upstream, `origin/HEAD`, divergence, clean tree и отсутствие network/repair внутри checker. Для Git-режимов также фиксируется состояние единственного `local_git_route` текущего BACK.

Terminal closeout переводит маршрутное разрешение в `closed`. Закрытая запись сохраняется как свидетельство, не разрешает новые коммиты и не заменяется второй записью для того же BACK.

## Фаза

После успешной проверки результат не должен оставаться в фазе `implementation`. Допустимы `verification`, `owner-review` или закрытие PLAN с открытием следующего PLAN.

## Границы

Технический PASS не является продуктовой приёмкой. Release/tag и GitHub write-действия требуют отдельного решения владельца.
