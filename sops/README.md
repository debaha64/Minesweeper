# SOP

SOP описывают процедуры исполнения. Системный контракт находится в корневом `SYSTEM.md`.

Граница слоёв: `docs/` хранит смысл продукта, объяснение, модель и справочник; `sops/` хранит процедуры, правила, действия и процессы; `templates/` хранит формы.

Ключевые процедуры:

- `project-management.md` — Управление проектом через ROAD/BACK/PLAN/logs.
- `sdlc.md` — короткий индекс фаз SDLC и точек контроля.
- `terminology.md` — ведение терминологии и русского технического стиля.
- `analytics.md` — `discovery`, интервью, исследование, терминология, требования и пакет решения владельца.
- `research.md` — product research-домены, свидетельства, closeout и archive boundary.
- `architecture.md` — технические варианты, архитектурное решение, ограничения и стратегия проверки.
- `sot.md` — источник истины: existing/missing repository вход, автоматический baseline-bootstrap, изоляция слоёв, маршрутное Git-разрешение, последовательные проверяемые результаты и отдельный переход принятого продукта.
- `system-editing.md` — режим `system-editing` для изменения системных файлов обвязки.
- `change-management.md` — процедура проверки связанных артефактов.
- `managed-agent-pass.md` — общий управляемый проход.
- `task-intake.md` — приём задач и переход после `discovery`.
- `interview.md` — процедура интервью, gates, CLI-output и чистое завершение.
- `verify-work.md` — проверки с учётом фазы.
- `clean-exit.md` — чистое завершение без подмены решения владельца.
- `system-diagnostics.md` — диагностика контракта.

Связка изменений стиля, шаблонов и вывода:

1. `terminology.md` — язык и термины.
2. `change-management.md` — синхронизация README/index и проверка связанных артефактов.
3. `system-editing.md` — разрешённый режим изменения системных файлов.
