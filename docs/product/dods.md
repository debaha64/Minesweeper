# Критерии готовности (DoD)

## Назначение

Критерии готовности результата по областям. DoD помогает понять, что можно передавать на проверку, но не заменяет продуктовую приёмку.

## DoD discovery

1. `PRODUCT_INPUT` зафиксирован как валидное `IE-000001`.
2. Product identity `Minesweeper` согласована между brief, PLAN и root README.
3. CLI-контракт, ограничения, риски и проверяемые результаты отражены в `docs/product/`.
4. Product paths и защищённые поверхности не изменены.
5. `bp_check.py` проходит с `0 fail, 0 warn`.
6. Следующий шаг остановлен на отдельном owner gate.

## DoD требований команды `count`

1. Синтаксис команды и zero-based координаты описаны.
2. Контракт валидного stdout/stderr/exit code описан.
3. Контракт invalid board и invalid coordinates описан.
4. Ограничение Python standard library и отсутствие хранения зафиксированы.

## DoD будущей реализации

1. Изменения ограничены `README.md`, `src/minesweeper.py` и `tests/test_minesweeper.py`.
2. Код и тесты изменены только после отдельного implementation decision.
3. Команда и валидный пример документированы.
4. Поведение `--smoke` сохранено.
5. Открытые технические долги записаны.

## DoD документации

1. `docs/product/` отражает актуальный смысл продукта.
2. `docs/architecture/` отражает архитектурные решения, если они есть.
3. `docs/technical/` отражает технические сведения продукта.
4. `docs/user/` обновлён, если изменилось пользовательское поведение.

## DoD проверки

1. Unit tests покрывают центр, край, угол, invalid coordinates и invalid board.
2. Существующий `--smoke` проходит.
3. Deterministic CLI smoke валидного примера печатает ровно `1`.
4. Invalid cases возвращают exit code `2`, пустой stdout и краткий stderr.
5. `bp_check.py` проходит с `0 fail, 0 warn`.
6. Результаты проверки записаны в `logs/quality.md`.

## Граница продуктовой приёмки

1. Технический PASS не является продуктовой приёмкой.
2. Выполнение DoD не является продуктовой приёмкой.
3. Продуктовая приёмка требует отдельного решения владельца.

## Не входит

1. Выпуск и тег.
2. GitHub-действия.
3. Автоматическое принятие продукта.
