# Первый старт

Первый старт связывает запрос владельца с текущим состоянием Product Unit. Он помогает определить продуктовый контекст и ближайшую точку решения, но не является разрешением на реализацию.

## Перед началом

1. Прочитайте root [README.md](../../README.md), [AGENTS.md](../../AGENTS.md) и [SYSTEM.md](../../SYSTEM.md).
2. Определите объявленный `SOT_MODE` и подготовьте соответствующее локальное состояние.
3. Для `sot_github` сначала выполните внешний preflight по [инструкции подготовки репозитория](github-repository-preparation.md).
4. После успешной входной проверки продолжайте по процедуре старта сессии.

Новый продукт начинается с выяснения цели, пользователя, границ и критериев готовности. Код, продуктовые тесты и выбор стека появляются только после отдельного решения владельца.

## Нормативные процедуры

1. [Старт сессии](../../sops/start-session.md).
2. [Режим источника истины](../../sops/sot.md).
3. [Управление проектом](../../sops/project-management.md).
4. [Управляемый проход агента](../../sops/managed-agent-pass.md).

Технические проверки не являются продуктовой приёмкой. Составной переход к GitHub всегда имеет два отдельных checkpoint: `sot_files -> sot_git -> sot_github`.
