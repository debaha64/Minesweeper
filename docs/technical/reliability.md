# Надёжность

## Смысл

Надёжность обвязки — способность восстановить текущую работу из файлового состояния без внешнего чата и без скрытого `state/`.

## Опорные артефакты

Состояние Product Unit восстанавливается из `AGENTS.md`, `SYSTEM.md`, `plans/`, `logs/`, `docs/`, `sops/`, `templates/` и `tools/`.

Для заполненного GitHub repository надёжность дополнительно требует проверяемый backup refs/settings/release metadata и независимый restore test до изменяющего перехода. Локальный checker использует уже полученные refs и не подменяет backup или внешний preflight.

## Риск, который снижает чистое завершение (`clean-exit`)

Чистое завершение (`clean-exit`) снижает риск потерянного контекста, скрытых непроверенных областей, забытых запретов, неочищенных временных файлов и неясного следующего шага.

## Почему важны повторяемые проверки

Повторяемые проверки дают сравнимое свидетельство между проходами. Они не заменяют владельца, но делают состояние проекта объяснимым.
