# Глоссарий

Реестр терминов, реально используемых в Product Unit. Правила добавления и изменения терминов находятся в [sops/terminology.md](../../sops/terminology.md); история замен — в `logs/terminology.md`.

## Управление проектом

- Каноническая форма: `Управление проектом`.
- Значение: ведение текущего состояния через `ROAD -> BACK -> PLAN` и связанные журналы.
- Не путать: не Конвейер разработки (SDLC).

## Конвейер разработки (SDLC)

- Каноническая форма: `Конвейер разработки (SDLC)`, далее `SDLC`.
- Значение: жизненный цикл продукта от замысла до отдельного выпуска.
- Не путать: не плановый контур `ROAD -> BACK -> PLAN`.

## Фаза SDLC

- Значение: текущее смысловое состояние жизненного цикла продукта.
- Где используется: `SYSTEM.md`, active PLAN и технические документы.
- Не путать: фаза сама по себе не разрешает действие.

## Точка контроля

- Допустимый технический alias: `gate`.
- Значение: проверяемая граница перехода между состояниями или решениями.
- Не путать: не технический PASS и не решение владельца.

## Маршрут решений

- Значение: последовательность от входа владельца к артефактам, точкам контроля и решениям владельца.
- Допустимый технический alias: `route` в machine values и check-id.
- Не путать: не дорожная карта и не один PLAN.

## Слоевое пакетное интервью

- Значение: интервью, в котором связанные вопросы сгруппированы по обязательным слоям.
- Где используется: `sops/interview.md` и `templates/interview.md`.
- Не путать: пакет вопросов не является решением владельца.

## Пакет документации продукта

- Значение: согласованные `docs/product/`, `docs/architecture/`, `docs/technical/`, `docs/user/` и `docs/terminology/`.
- Граница: документы хранят смысл; процедуры находятся в `sops/`.

## Операционный режим

- Значение: граница выполнения прохода поверх текущей фазы SDLC.
- Значения Harness: `product-work` и `system-editing`.
- Не путать: не `SOT_MODE` и не фаза SDLC.

## Источник истины (SoT)

- Каноническая форма: `Источник истины (Source of Truth, SoT)`, далее `SoT`.
- Значение: контур, который владеет текущим состоянием в объявленном режиме.
- Где используется: `AGENTS.md`, `SYSTEM.md`, `sops/sot.md`.

## `sot_files`

- Значение: файловый режим, в котором Git полностью вне проверки.
- Граница: Git executable не требуется, `.git` не читается, Git CLI не вызывается.

## `sot_git`

- Значение: режим локального Git repository с валидными `HEAD` и ветвью, чистым деревом и без remote.
- Граница: режим сам по себе не разрешает переход, commit или GitHub-действия.

## `sot_github`

- Значение: режим подготовленной локальной рабочей копии ожидаемого GitHub repository.
- Локальный контракт: один `origin`, совпадающая repository identity, upstream, remote refs и `origin/HEAD`.
- Граница: authentication, metadata и сеть принадлежат внешнему preflight.

## `SOT_GITHUB_REPOSITORY`

- Значение: условное поле `AGENTS.md` в форме `owner/repository`.
- Граница: существует ровно один раз только при `sot_github`; repository component не оканчивается суффиксом `.git`.

## Решение владельца

- Значение: явный выбор человека о смысле, переходе, реализации, приёмке, риске или выпуске.
- Не путать: подтверждение команды, технический PASS и вывод агента не являются решением владельца.

## Свидетельство

- Допустимый технический alias: `evidence` в machine values.
- Значение: проверяемая ссылка на факт, ответ, изменение или результат проверки.
- Граница: свидетельство не заменяет решение владельца или active PLAN.

## ROAD

- Значение: стратегическое направление локального планового контура.
- Где используется: `plans/roadmap.md`.

## BACK

- Русское пояснение: задача списка задач.
- Где используется: `plans/backlog.md` и связи PLAN.
- Не путать: не весь список задач.

## PLAN

- Значение: управляемый проход с целью, границами, решениями, точкой контроля и проверками.
- Где используется: `plans/active/` и `plans/completed/`.

## Проход

- Допустимый технический alias: `pass` в идентификаторах.
- Значение: фактическое исполнение управляемого пакета работ.
- Не путать: не сам файл PLAN.

## Внешний слой

- Значение: внешние сервисы и действия, например GitHub, PR, tag и GitHub Release.
- Граница: внешний слой не является побочным эффектом локальной проверки.

## Рабочий корень

- Допустимый alias: `корень Product Unit`.
- Значение: точный локальный каталог текущей Product Unit.

## Workspace

- Значение: внешняя рабочая среда, в которой ведётся работа над Product Unit.
- Граница: Workspace и Product Unit не являются одной сущностью; Product Unit не управляет Workspace.

## Product Unit

- Значение: самостоятельная продуктовая единица со своими документами, планами, журналами, процедурами, формами и проверками.
- Не путать: не Workspace и не один кодовый слой.

## BytePress Harness

- Значение: поставочная продуктовая обвязка для управляемой работы над Product Unit.
- Состав: документы, планы, журналы, SOP, шаблоны, инструменты, тесты и исследования Product Unit.

## Продуктовая часть

- Допустимый технический alias: `Product Part`.
- Значение: прикладной код и связанные тесты внутри Product Unit.
- Не путать: не системные слои Harness.

## Стартовая обвязка (Starter)

- Значение: базовая Product Unit до выбора и реализации конкретного продукта.
- Граница: стартовое состояние не содержит чужую историю или состояние выпуска.

## Исследовательский домен Product Unit

- Значение: локальный домен формального исследования в `research/<xxx>-<slug>/`.
- Граница: исследование не заменяет active PLAN и решение владельца.

## Архив исследования

- Значение: архив завершённого research-домена, созданный по отдельному разрешённому маршруту.
- Не путать: не архив выпуска.

## Реализация

- Допустимый технический alias: `implementation` в machine values.
- Значение: изменение продукта в границах отдельного implementation decision и active PLAN.

## Продуктовая приёмка

- Допустимый технический alias: `product acceptance` в machine values.
- Значение: отдельное решение владельца о принятии или отклонении результата.
- Не путать: технический PASS и выполнение DoD не являются приёмкой.

## Готовность к выпуску

- Допустимый технический маркер: `release-readiness`.
- Значение: отдельная проверка возможности выпуска.
- Граница: не создаёт tag, release или архив.

## Границы задачи

- Допустимый технический alias: `scope` в machine values.
- Значение: разрешённая область текущей работы; active PLAN может её только сузить.

## Проверки

- Допустимый технический alias: `checks` в check-id и machine values.
- Значение: механические и ручные действия, создающие техническое свидетельство.
- Граница: проверки не принимают продукт за владельца.

## Выпуск

- Допустимые технические маркеры: `release`, `release/tag`, `GitHub Release`.
- Значение: отдельно разрешённое опубликование принятого результата.
- Связанные понятия: точка выпуска и тега, архив выпуска и заметки выпуска; каждое действие сохраняет owner gate.

## Репозиторий

- `исходный репозиторий` — Git repository исходной истории.
- `продуктовый репозиторий` — Git repository конкретной Product Unit.
- Не использовать слово «репозиторий» как общий синоним Product Unit вне Git-контекста.

## DoD

- Расшифровка: `Definition of Done`.
- Значение: критерии готовности одного проверяемого результата; `DoDs` — набор таких критериев.
- Граница: выполнение DoD не является продуктовой приёмкой.

## Чистое завершение (`clean-exit`)

- Значение: завершение прохода с проверками, журналами, границами и следующим шагом.
- Граница: clean-exit не является решением владельца.

## Повышенный риск

- Допустимый технический alias: `high-risk`.
- Значение: задача или домен с повышенным риском ущерба, требующий явных ограничений и записи риска.
