# Интервью

## Слой N. Название слоя вопросов

При H2-требовании prompt или PLAN каждый слой выводится отдельным заголовком этого вида.

Краткое описание слоя вопросов.

---

### Вопрос 1

A. Вариант ответа 1 (Рекомендовано)
B. Вариант ответа 2
C. Вариант ответа 3
D. Другое (укажите свой вариант)

Рекомендация: вариант A, потому что это лучшее решение для текущего слоя.

---

### Вопрос 2

A. Вариант ответа 1 (Рекомендовано)
B. Вариант ответа 2
C. Вариант ответа 3
D. Другое (укажите свой вариант)

Рекомендация: вариант A, потому что это лучшее решение для текущего слоя.

---

Короткий формат ответа:

1A
2B

Ответьте на каждый вопрос или явно отложите его с причиной. После ответа агент фиксирует свидетельство `IE-*`; это не открывает реализацию.

Команда «Продолжай» относится только к текущему слою. Новый маршрут требует `A/B/C/D` или текстового решения владельца.

Полный `PRODUCT_INPUT` закрывает пять продуктовых слоёв; `next-transition` закрывается отдельно. Дополнительное подтверждение `Да` не требуется. Неполный вход требует уточнений.

После полного входа форма задаёт только краткое ветвление:

1. первоначальный продукт + `sot_files` -> обычный discovery;
2. `accepted-completed` + новая задача + `sot_files` + поддерживаемый `sot_git` -> один выбор маршрута по `sops/interview.md::## Выбор маршрута принятого продукта`;
3. уже объявленный `sot_git` -> отдельный `local_git_route`.

Выбор маршрута не разрешает реализацию.

После зафиксированного и проверенного discovery checkpoint реализация требует новой отдельной реплики владельца, например:

```text
Разрешаю реализацию <название и slice>.
```

Начальный запрос, ответ на интервью, преждевременная implementation permission и «Продолжай» не заменяют эту реплику. Если разрешение реализации пришло до PASS discovery, агент не создаёт OD и повторно запрашивает решение после checkpoint.

`SOT_MODE` не включается в продуктовое интервью. Начальный пакет не спрашивает разрешение `local_git_route` и не считает его предварительное упоминание решением. Фактическую ветку после `PRODUCT_INPUT` определяет список выше; transition, records и baseline выполняются по `sops/sot.md`. После проверенного discovery/evidence checkpoint агент отдельно запрашивает implementation decision.

Для перехода принятого продукта IE текущей задачи создаётся внутри transition checkpoint как `EVIDENCE_CLASS: transition`, использует долговечные raw locators полного `PRODUCT_INPUT` и выбора маршрута и затем переиспользуется discovery без копии.
